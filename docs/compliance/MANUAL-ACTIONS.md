## Godkendt dokumentversion — arbejdsgang

1. Lad juridisk reviewer gennemgå tekst/bilag og udfyld verificerede oplysninger. Axel godkender eksplicit den endelige version.
2. Opret et **nyt** versionsnummer og `status: published`; opdater dokumentets arkiverede supplier-snapshot fra den centrale leverandørkilde efter review; ret aldrig en historisk version eller publicér ved blot at ændre draft-status. Beregn SHA-256 af den kanoniske JSON uden sha256-felt (UTF-8, kompakte separators, bevaret Unicode). Arkivet gemmer også fuld tekst.
3. Opret ny migration med Supabase CLI og seed samme version/hash/document. Update public page/current version together. Database og app skal matche; ellers afvises accept.
4. Test afvisning af draft/ukendt hash, tenant isolation og idempotent accept. Informér kunder og lad dem selv acceptere. Eksisterende records ændres ikke.
